# 기존 학생의 프로세스2 자동 청구

기존 학생도 구매할 모든 강의에 등록되어 있지 않은 것이 확인되면 청구서를 자동 발송한다. 공개 웹은 공식 API로 기존 여부를 확인해 신청을 저장하고, 관리자 인증을 가진 전용 작업자가 강의별 수강생 목록을 읽는다. 웹 서버에는 브라우저 관리자 세션을 추가하지 않는다.

## 처리 순서

1. 신청 시 기존 학생을 선택하고 실제 전화번호 조회에서도 기존 학생이 발견된 주문을 대상으로 한다.
2. 이름·학생 번호·선택 보호자 번호를 단일 대치온 학생 ID와 대조한다. 보호자2와 비활성 학생도 기존 계정으로 인정하며 결제 수신 번호는 식별에 사용하지 않는다.
3. 구매할 모든 강의의 전체 수강생 수와 고유 학생 ID 목록을 조회한다. 빈 강의는 명시적인 0명 및 빈 목록 안내를 확인한다. 학생이 있는 강의는 필터 없는 전체 목록, 전화번호 검색 0명, 검색 해제 후 동일한 전체 목록을 모두 확인해야 미보유로 인정한다.
4. 미보유 결과와 학생 정보가 일치하면 기존 감사 원장에 담당자를 `시스템 자동 확인`, 사유를 `자동 보유 강의 확인:`으로 기록한다. 기존 트랜잭션·버전·학생/강의 바인딩 검증을 그대로 적용한다.
5. 청구 직전에 학생과 전체 강의 미보유 여부를 새로 확인한다. 신청 금액·상품 구성을 바꾸지 않고 청구서를 한 번만 발송한다.
6. 결제 후 처음 확인한 학생 ID와 프로필을 다시 대조하고 해당 계정의 첫 차시 및 공통 자료실 권한을 처리한다. 계정이 삭제되거나 다른 ID로 바뀌면 신규 계정을 대신 만들지 않는다.

## 확인 필요로 남는 경우

- 기존·신규 선택 불일치, 동명이인/형제 등 복수 계정, 이름·학생/보호자 번호 불일치.
- 하나라도 구매 대상 강의에 이미 등록되어 있는 경우. 주문 접수 후에는 일부 강의를 제외하거나 금액을 자동 변경하지 않는다.
- 전체 목록이 가상화/부분 표시되어 미보유를 입증할 수 없거나, 조회 실패·구조 변경·시간 초과가 발생한 경우.
- 관리자 보류, 청구·계정 생성·권한 등록 결과 불명확 등 기존 오류 처리 대상. 이런 주문을 자동 해제하지 않는다.

자동 재조회 대상은 청구·학생 생성·등록·관리자 조치 이력이 없는 최초 기존 학생 보류 주문으로 한정한다. 과거 관리자 수동 승인 경로와 기존 프로세스1은 유지한다. DB 스키마와 인증 범위 변경은 없다.

Sheets의 `중복 수강생 확인`은 자동 확인 성공 시 `통과`로 바뀌며 `중복 확인 사유`에 자동 확인 및 학생 ID가 기록된다. 이미 등록된 강의가 있으면 `확인 필요 사유`에 중복 청구 방지를 위한 발송 보류가 표시된다.
