# 프로세스2 상품별 할인코드

## 관리 및 구매
- 수업·묶음상품 추가/수정의 `할인코드 추가하기`에서 코드와 할인 후 최종 결제액을 등록한다. 교재비가 포함되면 그 금액도 포함한 최종 가격이다.
- 영문·숫자·밑줄·하이픈 1~64자이며 앞뒤 공백을 제거하고 대문자로 통일한다. 상품당 최대 50개, 상품 내 같은 코드 중복 금지. 동일 코드를 여러 상품에 등록할 수 있다.
- 정상가보다 낮은 1원 이상의 정수만 허용한다. 프로세스1·과목 개수별 변동 가격에는 적용하지 않는다.
- 장바구니는 코드 한 개만 적용한다. 해당 코드를 등록한 상품만 할인가로, 나머지는 정상가로 합산한다. 묶음상품 자체의 할인가만 사용하며 구성품 할인은 더하지 않는다.
- 적용할 수 없는 코드는 안내한다. 학생이 수정하거나 해제하면 정상 신청할 수 있다. 상품 선택 변경 시 다시 계산하고 가격 확인 동의를 해제한다.
- 관리자 코드 목록은 공개 상품 API와 장바구니 카탈로그에 노출하지 않는다.
- 신규생도 코드를 사용할 수 있다. 할인 자격에 대한 조회/차단은 없다. 기존 동일인 확인·기보유 강의 제외·묶음 중복 결제 방지는 그대로 유지한다.

## 금액 및 기록
- 할인 계산은 서버에서 한다. 학생이 가격·할인액을 전달하여 변경할 수 없다.
- 견적에는 당시 정상가/적용 코드/할인가와 최초 대치온 학생 조회 결과·조회시각을 저장한다. 신청 시 코드·가격·상품 변경은 재확인을 요구한다.
- 정상 접수된 주문은 불변 스냅샷의 금액으로 청구한다. 그 후 코드를 삭제해도 이미 접수된 주문의 가격은 변경하지 않는다. 코드 삭제는 새 견적에 반영된다.
- 별도 DB 테이블은 추가하지 않는다. 기존 견적 JSON/상품별 주문 스냅샷에 하위 호환 필드를 추가한다. 기존 주문은 할인 미적용으로 처리한다.
- 기존 여부는 계정 생성 전 학생/보호자 전화번호 조회 결과이며 결제 번호는 제외한다. 과거 유료 구매 이력이나 수강료 납부 여부를 증명하는 값은 아니다. 조회 불가·옛 주문은 확인 불가로 둔다.

## 업무 시트 확장
기존 37개 자동 열 뒤, `직원 메모` 앞에 8개 열을 삽입한다: 할인코드 적용 여부, 사용한 할인코드, 정상가 합계, 총 할인액, 상품별 정상가, 기존 수강생 조회 결과, 할인 사용 확인, 기존 수강생 조회시각.

`신규 수강생 할인 사용`은 빨간색으로 강조하지만 주문 상태/결제 가능 여부를 바꾸지 않는다. `할인 사용 · 기존 여부 확인 불가` 역시 확인용 빨간색이며 자동으로 신규로 판단하지 않는다.

시트는 기존 metadata와 정확한 이전 헤더/직원 메모가 일치할 때만 확장한다. 삽입과 헤더·서식 변경은 하나의 원자적 Sheets batch로 수행한다. 기존 데이터/메모/행 metadata는 유지하고 반복 실행 시 열이 중복 추가되지 않는다. 알 수 없는 헤더는 자동 수정하지 않는다. 기존 기록의 새 열은 해당 주문의 다음 시트 동기화 시 채워진다.

## 배포 순서
1. 기존 프로세스2 신규 청구 중지 상태를 유지하고 검수 중 미처리 주문을 확인한다. 프로세스1은 변경하지 않는다.
2. 새 웹/작업자 코드를 검수 환경에서 검사한다. 실제 청구·문자·대치온 등록을 테스트 목적으로 임의 실행하지 않는다.
3. 작업자의 기존 `node workers/daechion/orders.cjs --setup-sheets` 명령으로 시트 열을 확장하고 결과를 확인한다. 재실행은 같은 헤더를 인식하므로 중복 삽입하지 않는다. 실제 업무 시트에서는 기존 작업자의 구버전 쓰기가 동시에 실행되지 않도록 작업자를 먼저 중지한다.
4. 새 작업자로 복귀한 뒤 할인 없는 기존 주문도 정상 동기화되는지 확인한다. 구버전 작업자는 확장 헤더와 호환되지 않으므로 시트 확장 후 코드만 단독 롤백하지 않는다.
5. 웹의 단일 코드/복수 코드 설정, 일부 적용, 해제, 신규생 표시를 확인한 뒤 검수 접수를 종료하고 일반 청구를 복구한다. 새 검수 미처리 주문을 남긴 채 일반 발송을 켜지 않는다.

현재 배포된 운영 환경과 별개인 개발 브랜치의 구현 문서이다. 실제 적용 여부는 배포 기록을 확인한다.
