# 인증 유지 점검과 단계별 실패 기록

900원 실구매 검수에서 결제·등록·콘텐츠 접근·문자·Sheets는 완료됐지만 작업자 집계에 `failed: 1`이 남았다. 당시 집계는 모든 예외를 같은 숫자로 합쳐 과거 실패 단계를 확정할 수 없다. 이후 인증 유지 전용 모드의 `refreshed: true`를 확인했다. 이 보완으로 과거 원인이 증명됐다고 해석하지 않는다.

## 인증 화면 확인

인증 유지는 공식 API의 테넌트와 강의 ID를 대조한 뒤 해당 강의의 정확한 제목·수강생 목록 탭·고정 URL을 확인한다. 학생 추가 버튼은 확인 조건에서 제외한다. 학생 수나 추가 버튼의 표시 상태가 인증 여부를 결정하지 않게 한다. 버튼을 누르거나 학생·권한을 변경하지 않는다.

현재 실제 강의 11개는 모두 학생이 있어 빈 강의의 실화면을 재현하지 않았다. 새 강의를 만들거나 기존 학생을 제거해 재현하지 않는다. 빈 목록·학생 있는 목록·로그인 화면·다른 강의 URL·추가 버튼만 있는 불완전 화면은 격리 Chromium으로 검사한다. 틀린 화면에서는 인증 상태를 저장하지 않는다.

## 로그 형식

기존 `failed` 합계는 유지한다. 실패가 있을 때만 `failurePhases`에 `sessionRefresh`, `billing`, `paymentRead`, `enrollment`, `readyMessage`, `sheets`별 개수를 추가한다. 성공한 주기의 기존 출력 형식은 유지한다.

인증 오류에 공급자가 지정한 안전한 단계가 있으면 `sessionFailureStage`로 표시한다. 인증 유지 전용 모드는 같은 조건에서 `failureStage`를 표시한다. 허용 값은 `API_PREFLIGHT`, `BROWSER_LAUNCH`, `BROWSER_CONTEXT`, `SESSION_REFRESH`뿐이다. 오류 메시지·스택·전화번호·API 키·쿠키·상위 서비스 응답은 출력하지 않는다.

인증 유지 실패 후 기존 1분 재시도 간격과, 실제 콘텐츠 권한 검증 없이는 완료 안내하지 않는 조건을 유지한다. 인증 유지의 실패 합계를 금융 실패로 단정하지 않으며, 신청 원장의 결제·등록·권한·안내 상태와 함께 판단한다. 결과 불명 쓰기를 자동 재시도하는 변경은 없다.

DB 스키마·상품 프로세스·공급자 요청·가격·권한·실행 스위치를 변경하지 않는다. 운영 반영은 검사 통과한 변경을 검토한 뒤 별도로 진행한다.
