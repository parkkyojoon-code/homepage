# 수업 상품 파일 저장과 복구

`DATA_DIR/classes.json`의 배열 형식과 기존 상품 필드를 유지한다. 정상 파일을 처음 읽을 때 백업과 초기화 표식을 만든다. 저장은 파일 해시로 변경 여부를 확인한 뒤 같은 디렉터리에 임시 파일을 쓰고 `fsync`, `rename`을 수행한다. Linux에서는 디렉터리도 `fsync`한다. 저장 전의 정상 파일은 `classes.json.bak`에 같은 방식으로 보관한다. 이 백업은 최근 저장의 이전 버전이며 외부 정기 백업을 대체하지 않는다.

잘못된 JSON, 배열이 아닌 루트, 잘못된 기본 상품 필드, 파일 접근 실패는 503으로 중단한다. 파일이 없어도 `.bak` 또는 `.initialized`가 있으면 기본 상품을 다시 생성하지 않는다. 백업을 자동으로 화면에 표시하거나 덮어쓰지 않는다. 동시 편집의 파일 해시가 다르면 409를 반환하므로 다시 불러와 검토 후 저장한다. 저장 뒤 디렉터리 동기화가 실패하면 503이더라도 파일은 이미 바뀌었을 수 있다. 먼저 파일 상태와 화면을 다시 읽어 확인한다.

## 오프라인 복구

1. 앱과 같은 볼륨을 사용하는 모든 쓰기 프로세스를 중지한다. 복구는 상품 버전을 되돌릴 수 있으므로 현재 파일과 `.bak`을 별도 위치에도 보관한다.
2. 실제 데이터 디렉터리를 지정해 상태를 확인한다.

   ```sh
   node scripts/classes-store.cjs status --data-dir /app/data
   ```

3. `backup.valid`가 `true`인지 확인한다. `locked:true`이면 기존 쓰기 프로세스가 없는 것을 확인한다. 프로세스가 강제 종료되어 남은 `classes.json.lock` 디렉터리만 운영자가 수동으로 제거한다. 시간 경과만으로 잠금을 빼앗지 않는다.
4. 손상되거나 사라진 주 파일을 정상 백업으로 복구한다.

   ```sh
   node scripts/classes-store.cjs recover --data-dir /app/data --confirm-writers-stopped
   ```

   정상인 주 파일은 복구하지 않는다. 손상된 원본은 `classes.json.corrupt-<시각>-<고유번호>`에 보존하고 검증된 백업을 원자적으로 복원한다. 읽기 권한 문제는 먼저 해결해야 하며 백업도 손상되었다면 이 명령은 중단한다.
5. 상태 명령에서 `main.valid:true`를 확인한 뒤 앱을 시작하고 프로세스1 원래 상품, 프로세스2 개별/묶음상품, 가격과 공개 여부를 확인한다.

`classes.json.lock`은 같은 볼륨을 쓰는 앱 프로세스 간 저장을 직렬화한다. 파일 잠금/원자적 이름 변경을 지원하지 않는 저장소나 서로 다른 볼륨을 쓰는 다중 인스턴스에는 이 저장 방식을 사용하지 않는다. 저장 도중의 외부 수동 편집은 피하고 복구 명령을 사용하는 동안 앱을 중지한다.

대표 이미지 교체·수업 삭제 시 이전 이미지 파일은 백업이 참조할 수 있어 자동 삭제하지 않는다. 이미지 디렉터리도 외부 백업에 포함한다. 사용하지 않는 이미지는 현재/백업 카탈로그 모두에서 참조하지 않는 것을 확인한 뒤 별도로 정리한다. 갤러리 사진의 명시적 삭제는 기존 동작을 유지한다.

관리자 목록을 읽지 못했거나 저장 중 파일 장애가 확인되면 추가·수정·삭제를 잠그고 오류와 ‘목록 다시 불러오기’를 표시한다. 편집 입력은 남겨 두며 목록 재조회가 성공해야 저장을 다시 허용한다. 409 충돌은 목록으로 돌아가 해당 수업을 다시 열어 현재 값을 확인한 뒤 반영한다. 구매자 수업 목록의 다시 시도도 실제 데이터를 새로 조회한다.

새 수업·묶음 등록 화면은 한 번 정한 자동 ID를 재시도에도 유지한다. 저장은 성공했지만 응답이 실패한 경우 목록 재조회 후 같은 입력을 다시 저장해도 다른 ID의 중복 상품을 생성하지 않는다. 이미 사용 중인 ID라는 안내가 뜨면 목록으로 돌아가 해당 상품을 확인한다.

검증: `npm run test:classes-store`는 임시 디렉터리의 손상·실제 별도 프로세스 동시 수정·쓰기 및 교체 실패·불명확한 저장 결과·복구를 검사한다. 전체 웹 빌드 후 `node --test tests/daechion-bundle-components-http.test.mjs`로 HTTP 응답과 기존 상품 보존을 검증한다. 로컬 Playwright/Chrome이 준비된 환경에서는 `node tests/classes-admin-browser.mjs --local-only`로 오류 시 저장 잠금·입력 보존·재조회 동작을 검사한다. 이 검사는 별도 임시 데이터와 합성 응답만 사용한다.
