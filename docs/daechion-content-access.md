# 대치온 콘텐츠 권한 보완

## 실제 검증된 경로

2026-11-07, 검수 학생 6105662를 강의 6006577 / 차시 6047156에 API로 등록한 상태에서 관리자 화면의 일괄 학생 추가로 동일 학생과 동일 차시를 다시 지정하고 세 권한을 모두 선택했다. 삭제 없이 기존 영상 8개의 권한 인원이 30→31명이 됐고 학생 세션에서 영상 81104의 실제 재생을 확인했다. 출결은 미정으로 유지했다. 이는 UI 경로의 실제 검증이며 Railway의 무인 브라우저 실행 검증과 구분한다.

## 처리와 저장

1. 기존 결제·본인 확인을 통과한 프로세스2 신청만 처리한다.
2. API 등록 응답의 학생 ID·강의 ID·차시 ID들을 확인한다.
3. 등록 테이블에 학생 ID, 차시 ID 목록, `access_state=PENDING`을 저장한다.
4. 별도 브라우저 작업자가 지정 사이트의 관리자 화면에서 해당 학생만 다시 선택하고 세 권한을 적용한다. 출결 메모 복사는 해제한다. 제거 기능은 사용하지 않는다.
5. 페이지를 다시 열어 각 차시의 영상·자료와 강의 자료실 파일의 실제 권한 선택 상태를 조회한다. 파일 이름이 중복되거나 UI가 바뀌어 확정할 수 없으면 보류한다.
6. 확인된 대상 ID가 일치할 때만 `VERIFIED`로 저장하고 등록을 DONE으로 끝낸다. 모든 연결 강의가 완료돼야 안내를 예약한다.

로그인 만료, 브라우저 오류, 권한 미확인, 저장 결과 불명은 `content_access_unverified`로 보류한다. API 재등록이나 안내 문자를 무조건 반복하지 않는다. 관리자가 실물을 확인해 수동 완료를 기록하면 `MANUAL`로 남는다. API 성공 뒤 권한 적용 중 보류·취소가 들어오면 DB 상태를 재확인해 완료/안내를 막는다. 외부 권한 부여와 DB 변경은 원자적이지 않으므로 이미 적용됐을 수 있는 권한은 수동으로 확인/회수한다.

004 마이그레이션은 열 추가만 한다. 기존 DONE 행을 검증 완료로 간주하거나 외부 등록을 재실행하지 않는다. 이전 마이그레이션의 체크섬과 기존 Sheets/로그인/프로세스1은 유지한다.

## 배포 준비 상태

현재 자동 실행은 계속 비활성이다. 브라우저 실행부는 `workers/daechion/Dockerfile.browser`에 격리했고 기존 경량 이미지와 홈페이지에는 브라우저 패키지를 추가하지 않았다. 시작 명령 기본값도 `--check`다.

다음 검수 전에는 다음 설정을 활성화하지 않는다.

- `DAECHION_CONTENT_BROWSER_ENABLED=true`: 선택 이미지의 실행 허용.
- `DAECHION_CONTENT_BROWSER_VERIFIED=true`: 실제 서버에서 지정 검수 계정의 적용·조회까지 통과한 뒤 설정.
- `DAECHION_ACCESS_POLICY_VERIFIED=true`: API 단독 성공이 아니라 콘텐츠 권한 확인 단계를 포함하는 전체 경로 검수가 완료됐을 때만 설정.
- `DAECHION_BROWSER_STORAGE_STATE`: 해당 사이트 관리자 인증 상태를 담은 비공개 JSON. 채팅·Git·로그·CI 아티팩트에 저장하지 않는다. 로그인 쿠키 또는 토큰이므로 관리자 자격증명과 동일하게 취급한다.

인증 상태는 본인이 로그인하는 별도 Chrome 임시 프로필에서 생성할 수 있다. 로컬에 설치된 정식 Chrome을 사용하며 기존 Chrome 프로필을 변경하지 않는다. 작업자 패키지 폴더에서 의존성을 설치하고 다음 명령을 실행한다. 실제 로그인은 본인이 완료한다. 비밀번호를 코드나 명령행에 입력하지 않는다.

```
cd workers/daechion/browser
npm ci
npm run auth -- --lecture-id 6006577
```

마지막 명령은 검수 강의를 열고 직접 관리자 로그인을 마칠 때까지 기다린다. 로그인 후 터미널에서 Enter를 누르면 관리자 화면 접근을 확인하고 `.auth/admin.storage-state.json`에 저장한다. 이 파일은 Git과 Docker 빌드에서 제외한다. 생성한 JSON은 별도 검증 작업자의 Railway 비공개 변수에 직접 입력한다. 현재 일반 Chrome의 로그인 상태가 서버에 자동 전달되는 것은 아니다. 세션 만료 때는 재인증이 필요하며 자동 우회나 비밀번호 초기화는 하지 않는다. 공식 API가 동등한 권한 기능을 제공하면 이 브라우저 어댑터를 교체할 수 있다.

Windows 실행 파일은 ASCII 본문·CRLF 줄바꿈과 실행 파일 기준의 상대 경로를 사용한다. 한글 절대 경로를 배치 소스에 직접 넣지 않는다. 인증 도우미는 실패 단계만 표시하며 브라우저 시작 단계의 오류만 `.auth/browser-start-error.json`에 로컬 기록한다. 이 단계는 계정/토큰/URL 입력 전이다. 인증 상태와 시작 진단 파일은 서버 빌드나 Git에 포함하지 않는다.

## 검증 범위와 남은 일

실제 서버 검수는 자동 처리 주기 대신 별도 단일 대상 명령으로 실행한다.

```
node scripts/daechion-content-verify.cjs --student-id 6105662 --lecture-id 6006577 --verify
```

이 명령은 `DAECHION_CONTENT_TEST_ONLY=true`, `DAECHION_CONTENT_TEST_STUDENT_ID=6105662`, `DAECHION_CONTENT_TEST_LECTURE_ID=6006577`의 세 값이 명령 인수와 정확히 일치하고 비공개 API 키·테넌트·브라우저 인증이 연결돼 있어야 실행된다. 지정 학생의 권한 적용·확인만 수행하며 DB·청구·문자·전체 작업 주기는 실행하지 않는다. 단일 검수 호출에 한해 브라우저 검증 전 플래그 제한을 통과시키며 실제 환경변수나 일반 자동화의 활성화 상태는 바꾸지 않는다. `--check` 시작 명령을 이 단일 검수 명령으로 바꾸는 것은 검수 준비 완료 후 별도 실행 단계다.

CI는 가상 학생과 로컬에서 제공하는 HTML만 사용하는 실제 Chromium 계약 검사를 실행한다. 동일 이름의 다른 학생, 변경된 차시, 잘못된 테넌트, 미확인 권한, 적용 도중 보류를 검증한다. 실제 대치온 쿠키나 API 키는 CI에 제공하지 않는다.

운영 활성화 전에는 서버의 관리자 인증 연결, 화면 구조 일치, 강의 자료실에 파일이 있는 강의, 보호자 2 번호 사례, 실제 청구→권한→문자 전체 흐름을 검수해야 한다. 화면 구조가 달라지면 자동으로 추측해 조작하지 않고 보류한다. 이번 코드 반영만으로 실제 무인 운영 검증이 끝난 것으로 간주하지 않는다.
