# 브라우저 작업의 시간 제한과 중단

콘텐츠 권한 처리와 읽기 전용 인증 갱신은 모두 호출 시점부터 최대 300초를 사용한다. DB 세션 확보, 공식 API 사전 검사, Chromium 시작, 브라우저 컨텍스트 생성, 화면 확인, 인증 상태 저장과 브라우저 종료를 포함한다. 마지막 5초는 종료를 위해 확보하므로 화면 작업은 최대 295초 안에 끝나야 한다. 테스트에서만 공급자 생성 옵션으로 짧은 제한을 주입한다. 운영 환경 변수나 재시도 정책을 추가하지 않는다.

주문 DB의 결제 유효 기간은 계속 3분이다. 운영 주문 작업자는 학생 생성 직전과 신원 확인 완료 전, 강의 처리 전, 브라우저의 각 실제 쓰기 직전과 최종 권한 검증 완료 기록 전에 현재 청구서를 다시 조회한다. 결제 제공자 조회 동안 주문 DB 트랜잭션을 열어 두지 않는다. 조회 뒤에는 기존 주문 보류·취소 상태와 학생, 작업 lease, 고정한 첫 차시를 다시 대조한다. 더 최근 조회에 밀린 `STALE` 응답은 권한을 허용하지 않는다. 브라우저가 3분 이상 걸렸다는 이유로 결제 유효 기간을 늘리지 않는다.

대치온이 등록 성공을 응답한 뒤에는 같은 유효한 작업 lease·학생·차시가 유지된 경우에만 성공 응답을 기록한다. 이 사실 기록은 결제 조회 시각 경과 때문에 버리지 않지만, 취소나 관리자 보류로 lease가 해제되었다면 기록하지 않는다. 최종 `VERIFIED`와 완료 안내 대기는 별도의 현재 결제 확인을 통과해야 한다. 첫 쓰기 직전 결제 조회만 실패했고 아직 어떤 쓰기 검사도 성공하지 않은 작업은 미시도 사실을 확인한 뒤 대기로 돌릴 수 있다. 한 번이라도 쓰기를 허용한 뒤의 조회 실패나 결과 불명은 등록·성공 응답 기록을 보존한 채 확인 필요로 남기며, 다음 작업자가 등록 화면을 자동 재실행하지 않는다.

DB 연결 상실에 따른 중단 수신기는 첫 비동기 검사 전에 등록한다. DB 연결이 끊기면 advisory lock도 해제되므로 소유 Chromium에는 일반 종료 유예 없이 즉시 강제 종료를 요청한다. 중단 후에는 지연된 API·화면 호출의 결과로 다음 동작이나 저장을 진행하지 않는다. 늦게 생성된 브라우저는 닫고, 늦게 생성된 컨텍스트는 페이지를 열지 않고 닫는다. 기존 결제·보류 검사와 학생 확인을 거쳐야만 권한을 제출하며, 결과 불명 쓰기를 자동 재시도하지 않는다.

운영 공급자는 Playwright의 공개 `launchServer`, `connect`, `BrowserServer.close`, `BrowserServer.kill`, `BrowserServer.process` API로 이 작업이 직접 만든 Chromium만 종료한다. 일반 종료가 제한 시간 안에 끝나지 않으면 해당 서버를 강제 종료한다. 강제 종료 Promise도 멈춘 경우에는 같은 서버가 반환한 자식 프로세스에 `SIGKILL`을 보내고 종료를 확인한다. 설정이나 시스템 검색에서 가져온 PID를 종료하지 않는다.

끝내 브라우저 종료를 확인하지 못하면 호출자는 제한 시간 안에 `CONTENT_ACCESS_UNCONFIRMED` 오류를 받는다. 오류에는 기존의 안전한 `stage`와 `browserTerminationUnconfirmed: true`만 붙는다. 이 경우 공급자는 후속 실행을 거부하고 DB 세션의 작업 Promise를 미완료 상태로 유지한다. DB 연결이 살아 있으면 공유 advisory lock도 유지된다. 브라우저가 계속 쓸 가능성이 있는데 다른 작업자가 같은 인증 세션을 사용하는 상황을 막기 위한 격리다. 운영자는 해당 작업자 프로세스와 소유 Chromium을 종료·교체한 후 원장의 실제 등록·권한 상태를 확인해야 한다. 이 문서의 변경만으로 배포하거나 권한 처리를 다시 실행하지 않는다.

공급자의 읽기 전용 `isAvailable()`은 격리 여부를 즉시 알려준다. 주문 작업자는 등록 도중 격리가 발생해도 기존 인증 `READY` 기록을 그대로 신뢰하지 않는다. 같은 주문의 다음 강의와 후속 주문·안내·Sheets 작업을 중단하고 `browserRestartRequired: true`와 제한된 오류 코드만 출력한다. DB 진단 기록이나 잠금 해제까지 실패하거나 응답하지 않아도 이 종료 신호를 일반 재시도 오류로 바꾸거나 DB 정리 완료까지 기다리지 않는다. 뒤늦게 완료되는 호출이 후속 업무 쓰기를 진행하지 못하도록 격리 상태를 유지한다.

반복 주문 작업자와 인증 유지 전용 작업자의 CLI는 종료 불명 상태에서 종료 코드 1로 프로세스를 끝낸다. 열린 DB 풀·타이머가 있어도 종료되며, Railway의 컨테이너 재시작 정책이 전체 프로세스와 소유 Chromium을 교체한다. 운영 서비스의 Restart Policy가 `Always` 또는 실패 재시작으로 설정돼 있어야 한다. 브라우저 잠금이나 결과 불명 쓰기 기록을 임의로 해제하지 않는다. 새 프로세스는 기존 원장 기록과 현재 결제를 다시 확인하며, 결과 불명인 청구·등록을 재실행하지 않는다. 일반적인 일시 조회·세션 갱신 오류는 기존 재시도를 유지한다.

합성 테스트는 사전 검사, 시작, 컨텍스트, 라우팅, 페이지 생성, 인증 갱신, 상태 저장과 종료의 정지를 짧은 타이머로 검사한다. 중단 후 늦은 컨텍스트·등록 검사 응답이 와도 페이지나 등록 쓰기가 진행되지 않는지, 종료 확인 전까지 공유 lock을 유지하는지도 검사한다. Chromium 검사는 로컬 HTML로 모든 요청을 응답하며 공급자 계정이나 실데이터를 사용하지 않는다.
