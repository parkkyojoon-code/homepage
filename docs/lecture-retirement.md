# 신규 강의 시스템 운영 종료

2026-11-06 요구사항 변경: 기존 홈페이지와 수업 신청을 유지하고 판매 항목만 추가한다. 영상·수강 권한은 대치온을 사용한다. 이전 신규 회원·자체 강의실·로그인 통합 계획은 진행하지 않는다. `student-account-transition.md` 등의 과거 설계는 현재 구현 지침이 아니다.

## 코드 변경

`middleware.ts`에서 `/lectures`, `/admin/lectures`, `/api/lectures`와 그 하위 경로를 모든 HTTP 메서드에 대해 410으로 종료한다. 신규 가입·로그인·주문·결제 콜백·내부 작업자 API도 포함한다. 환경변수만 바꾸어 다시 켜는 플래그는 제공하지 않는다. 기존 `/classes`, `/apply`, `/my`, `/admin`과 기존 API는 영향을 받지 않는다.

새 경로는 `no-store` 및 `noindex, nofollow`를 반환한다. 페이지에는 기존 수업 신청과 홈 링크를 제공한다. 데이터나 인증 쿠키는 변경하지 않는다. 코드와 마이그레이션을 당장 물리적으로 제거하지 않아 과거 기록·복구 도구를 보존한다. 신규 기능은 이미 DB에 저장된 기록을 삭제하지 않고도 종료된다.

기존 학생 프로필에서 `password`와 `password_plain`을 응답하지 않도록 한 보안 수정은 유지한다. 기존 학생 로그인, 관리자, JSON volume, Sheets, 청구 프로그램은 변경하지 않는다.

## 검증

Next production build 후 `node --test tests/legacy-auth-http.integration.mjs`를 실행한다. 임시 파일과 loopback 서버, 빈 신규 DB 설정에서 기존 학생/보호자/관리자 로그인 및 프로필 비밀번호 비노출, 기존 공개 페이지·수업 관리·신청 입력 검사, 신규 페이지와 API 모든 메서드 종료를 확인한다. 실제 학생 파일·계정·결제선생·Sheets에는 쓰지 않는다.

## Railway 적용 순서

1. 신규 worker가 상시 실행 중인지 확인하고 종료 유지한다. 자동 배포·Cron도 확인한다. 기존 register_checker와 청구 프로그램은 대상이 아니다.
2. 기존 웹 pre-deploy의 신규 DB migrate/check 명령을 해제한다. 기본 build/start와 `/app/data` volume은 유지한다.
3. 검사한 종료 코드를 배포하고 기존 공개 경로 200, 신규 경로 410을 확인한다. 신규 DB가 없어도 런타임과 후속 배포가 가능해야 한다.
4. 검증용 웹과 신규 DB의 불필요한 실행을 중지한다. DB volume과 결제 검수 이력은 보관한다. 삭제 시 별도 보관·복원 계획을 먼저 확인한다.
5. 전용 신규 인증·변수와 불필요한 코드/CI 정리는 후속으로 수행할 수 있다. 실제 적용 상태는 저장소 밖 종료 보고서에 기록하며, 이 절차 문서만으로 실행 완료를 주장하지 않는다.
